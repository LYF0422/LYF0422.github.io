# 在线写作台

网站部署后访问 **https://lyf0422.github.io/studio/**。电脑和手机均可使用，页脚的 **Write** 也能进入。

文章页标题下方的“编辑文章”会在当前标签页进入写作台，并打开对应文章。该文章若有本机备份，会优先恢复本机修改；否则连接 GitHub 后读取文章。进入其他文章前会保存当前草稿。已移动或删除的文章会显示提示，可在左侧文章库重新选择。

本地开发使用 `pnpm dev`，然后打开终端地址下的 `/studio`。本地预览和线上后台使用相同的 GitHub 仓库配置。

## 第一次连接 GitHub

后台直接与 GitHub API 通信，不需要额外服务器或数据库。

1. 打开 [GitHub Fine-grained personal access tokens](https://github.com/settings/personal-access-tokens/new)。
2. 为令牌取一个容易识别的名字，例如 `Yifan Writing Studio`，设置合适的有效期。
3. Repository access 选择 **Only select repositories**，仅勾选 `LYF0422/LYF0422.github.io`。
4. 在 Repository permissions 中，将 **Contents** 设置为 **Read and write**。Metadata 保持默认即可。
5. 创建令牌，在写作台的“连接 GitHub”窗口中粘贴。不要把令牌写入代码或提交到仓库。

勾选“在当前标签页保持登录”后，令牌只保存在当前浏览器标签页的 sessionStorage，刷新后无需重输。退出登录或结束该标签页会话后清除。不勾选时仅在当前页面内存中保留；令牌不会写入 localStorage、IndexedDB、文章或 Git 提交。

不同设备需要各自连接 GitHub。推荐为不同设备创建各自的仓库专用令牌，方便单独撤销。

## 写作和排版

- 点击“新建记录”，在弹窗中选择类型、填写网址或上传 PDF，并检查自动读取的标题、作者、摘要、年份等信息。确认后创建；取消不会新增记录或改动原文章。Anime / Game 也可在弹窗中搜索站内作品库。
- 论文网址支持 arXiv、OpenReview、ACL、CVF、NeurIPS、PMLR 的常见论文页面。其他 HTTPS 网页会尝试读取论文 PDF 元数据或下载按钮；没有 `.pdf` 后缀的直接下载地址也可识别。网页或文件受网络、跨域或登录限制时，仍可上传本地 PDF，已填写的信息会保留。
- 右键左侧文章（手机点“⋯”），选择“修改文章信息…”可再次打开弹窗；顶部“修改信息”也可修改当前文章。修改先保存在本机，点“发布”或“存草稿”后同步。不同分类的正文模板继续在文章内编辑。
- “封面与文章选项”折叠保存封面、发布时间和文件名；正文行距放在排版工具栏中。
- 工具栏支持标题、加粗、斜体、下划线、删除线、高亮、列表、引用、链接、代码、分隔线与表格。
- 直接粘贴截图，或把图片拖进正文，也可使用“插入图片”按钮。静态图片自动缩小到最长边 2400px 并压缩；GIF 保留原文件。
- 点击图片，可设置宽度、对齐、说明文字和替代文字，也能将图片设为文章封面。
- “预览”查看排版效果；正文行距可以在排版工具栏中调整。
- 手机顶部的列表按钮打开文章库，每篇旁边的“⋯”与电脑右键菜单相同。电脑可点“专注”收起文章库，刷新后会回到上次打开的记录。
- 顶部“存草稿”“发布”直接同步当前文章；“发布选项”中可开启自动同步、重新载入 GitHub 版本和查看部署进度。

文件存储为标准 `.md`：YAML frontmatter + HTML 正文。HTML 保留图片宽度、说明、对齐和表格排版；文章仍由 Astro 的 Markdown 内容集合构建，也可以用文本编辑器修改。自定义 MDX 组件不在可视化编辑范围内。

## 本机保存、同步草稿和发布

Anime / Game 的站内热门作品检索与评分、Photo 多图相册、Paper Reading 原文阅读与批注，见 [分类记录与陈列指南](COLLECTIONS.md)。标题上方可以直接切换分类。作品资料来源于 Bangumi，每周更新精选库，检索时无需访问 Bangumi。Paper Reading 创建后默认只显示 PDF 与批注；“独立笔记”可展开已有正文与写作工具，原有笔记会保留。网址支持 arXiv 摘要页/PDF、OpenReview、ACL Anthology 以及 HTTPS PDF 下载地址；粘贴 Markdown 链接也可识别。导入时下载并检查 PDF（最大 20 MB），提取可识别的信息并保存到本机，发布时一同上传。之后阅读已导入的论文无需重新连接原论文网站。arXiv 优先读取站内已有缓存。尚未缓存且浏览器连不上 arXiv 时，可点“通过 GitHub 获取”：连接 GitHub 后由仓库任务下载公开论文，通常等待 1–3 分钟后继续自动填充；也可从原文下载后上传 PDF。错误原因直接显示在网址旁，弹窗会保留已填信息。获取公开论文会新增缓存和请求记录，但不会创建或发布文章。尚未解析成功时不会创建空论文记录。阅读器支持大屏阅读、选文高亮、框选高亮和页面/位置批注。点选页面标注后可删除，也可在批注列表删除，并支持撤销删除。批注随文章保存与发布。

**本机自动保存**：停止输入后约 650ms，文字、记录卡和附件保存到这个浏览器的 IndexedDB。离线也能继续写。未同步内容不会出现在其他设备上；清除浏览器站点数据会删除这些本机备份。

**同步为草稿**：文章和使用的图片、PDF 会在同一个 Git 提交中上传。文章包含 `draft: true`，不会显示在博客、RSS、搜索或站点地图中。草稿文件仍然存在于公开 GitHub 仓库，适合未完成的文章，不适合存放私人信息。

**发布 / 更新发布**：文章保存为 `draft: false`，提交到 `main` 后由现有 GitHub Actions 自动构建并发布。同步成功表示 Git 提交成功；网站需要等 Actions 完成后更新，可点击“查看网站部署进度”。未来的发布时间遵循站点现有定时展示规则，需要新的构建触发才会显示。

**修改后自动同步**：手动开启后，停止输入 10 秒自动提交。新记录按草稿同步；已经发布的文章会更新已发布内容。需要临时离线时可关闭此开关。本机自动保存不受影响。

文章写入 `src/content/posts/<文件名>.md`，图片写入 `public/images/studio/`，PDF 写入 `public/documents/studio/`。同步后固定文件名，避免更新文章时意外更换地址。移除附件不会删除 GitHub 历史中的文件。

## 删除本机记录

右键左侧文章，或点击文章旁的“⋯”，选择“删除本机记录”并确认。也可以在正文内展开“封面与文章选项”后删除当前本机记录。未同步的修改会丢失；GitHub 草稿和网站上已发布的文章会保留，也可从“GitHub 文章”重新打开。

## 整理和删除 GitHub 文章

右键文章或点“⋯”，选择“修改分类和标签”。整理其他文章时，当前正文不会切换。本机记录保存在当前浏览器；从“GitHub 文章”操作则只同步分类与标签，保留原有正文。

选择“删除 GitHub 文章…”并确认，会提交删除这篇 Markdown 文件，网站在部署完成后移除该文章。照片、PDF 和 Git 历史保留。本机已有的备份会转成草稿，并关闭自动同步，防止自动重新上传。所有远端修改都会检查文章版本，其他设备已更新时会停止操作。

## 在另一台设备继续

1. 连接同一个仓库。
2. 在“GitHub 文章”中打开需要继续的文章或草稿。
3. 写作后同步即可。

每次同步都会检查文章在 GitHub 上的版本。如果其他设备已更新同一篇文章，后台会停止同步并保留本机内容。可以先导出 Markdown，再在“发布选项”中“从 GitHub 重新载入”后合并修改。系统不会强制覆盖远端分支，也不会提交编辑器以外的本地项目文件。

## 仓库配置

公共配置位于 `src/data/studio.ts`：仓库、分支、文章目录、媒体目录和站点地址。这里不能存放令牌。

写作台不使用公共页面的客户端路由，不进入搜索索引或站点地图，并带有 `noindex,nofollow`。后台入口可以公开访问；读取私有权限或写入仓库均由 GitHub 验证。

## 验证

```sh
pnpm build
pnpm test:studio
```

集成测试模拟 GitHub 和站内作品库，并阻断外部 Bangumi 请求，覆盖作品检索和评分、相册排序、论文转换和 PDF 上传、图片排版、持久草稿、附件原子提交、跨设备版本冲突和自动同步，不会修改真实 GitHub 仓库。测试在本机优先使用已安装的 Microsoft Edge，其他环境可安装 Playwright Chromium。同步脚本的完整性检查可用 `node --test scripts/sync-bangumi.test.mjs` 验证。

## arXiv 备用获取

`.github/workflows/import-paper.yml` 处理 `.paper-imports/requests/` 中的公开 arXiv 编号。它只允许 arXiv 下载地址及对应重定向，限制 PDF 为 20 MB，校验文件头并记录 SHA-256；浏览器在保存前再次校验。连接令牌只提交请求、读取结果，需要的仍是 Contents 读写权限。令牌不会传给 arXiv 或写入请求文件。

PDF 和缓存索引写入 `public/documents/studio/arxiv/`，结果写入 `.paper-imports/results/`。下载任务会触发一次网站部署，使之后导入相同编号可直接从本站读取；从任务取回 PDF 时无需等待站点部署。取消弹窗保留当前文章，已经提交的公开论文获取任务可能继续完成。任务提交使用正常的 Git 提交，并保留并发的文章修改。

下载脚本检查：`python3 -m unittest discover -s scripts -p test_sync_papers.py`。
